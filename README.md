# 全景可视化数字工厂

面向制造场景的网页管理与三维仿真平台。以星铸工厂的模拟装配线为例，从同一张工单追踪设备工况、批次报工、物料补充、质量异常和现场处置。

## 当前进展

| 模块 | 可演示的业务 |
| --- | --- |
| 生产监控与现场处置 | 准备可重复的答辩场景，演示温控越限停产、降温后人工确认复产、批次抽检和设备点检，按工单核对处置记录 |
| 仓储物料 | 模拟缺料停产和 A-01 库位补料，核对退料、补料成对流水以及同批次恢复报工 |
| 三维车间 | 网页内嵌 Unity WebGL 装配三线，按当前演示轮次同步设备、工单、批次和工况。Unity 也可导出 Windows 独立演示程序 |
| 质量分析与排班 | 用模拟样本查看分层风险差和证据问答。用本机三个节点演示联邦训练。按班表、岗位和技能辅助派单与复核 |
| 网页访问 | 电脑和手机浏览器使用同一套 Web 平台。页面按屏幕尺寸调整布局，手机通过局域网访问 |

## 快速开始

在 Windows 上安装 **Python 3.9+** 和 **MySQL Server 8.0.16+**，将 Python 加入 PATH。首次安装 Python 依赖需要网络。

| 使用场景 | 启动方式 | 打开方式 |
| --- | --- | --- |
| 本机网页与三维车间 | 在仓库根目录双击 `start.bat` | 等服务就绪并打开浏览器。默认地址为 `http://127.0.0.1:8765` |
| 手机浏览器访问 | 电脑运行 `start-lan.bat` | 手机和电脑接入同一局域网，用手机浏览器打开启动窗口显示的地址 |
| Windows 独立三维演示 | 导出 Windows 构建后运行 `unity/启动仿真工厂.bat` | 双击脚本即可打开独立程序 |

没有本机数据库配置时，启动脚本会创建 Python 虚拟环境、安装依赖并初始化项目专用 MySQL。需要提前初始化或在首次配置时指定 MySQL 端口，可先运行 `setup.bat`。新建数据库的管理员初始登录信息见启动窗口。

使用 `start.bat` 后，在星铸工厂加载已导出的 WebGL 车间。构建缺失时显示车间示意图。新克隆可直接使用网页业务功能，三维构建按 [Unity 仿真工厂](#unity-仿真工厂) 一节导出。

[统一运行说明](README_统一运行说明.md) 包含部署、账号、手机访问、故障排查和数据恢复步骤。

## 技术栈与目录

```text
factory/
├─ frontend/       页面、样式、交互和背景
├─ backend/        Python接口、因果分析、联邦训练、测试和工具
│  ├─ sql/         MySQL主业务库、排班模块、节点库建表脚本
│  ├─ assets/      登录后可访问的三路监控演示视频
│  └─ fixtures/    初始化业务快照
├─ unity/          Unity 6 仿真工程与 Windows、WebGL 导出入口
├─ data/           本机连接配置、数据库和上传文件（首次配置生成）
├─ setup.bat       首次配置MySQL和Python依赖
├─ start.bat       电脑启动
├─ start-lan.bat   手机局域网启动
└─ run.py          前后端统一启动入口
```

前端使用原生 HTML、CSS 和 JavaScript。Python 标准库 `http.server` 提供网页、HTTP API 和 WebGL 静态资源，通过 PyMySQL 读写 MySQL。业务表使用 InnoDB、utf8mb4、外键和事务。

## 本机数据库与演示账号

默认专用 MySQL 实例监听 `127.0.0.1:3307`，可与常用的 3306 端口实例共存。应用通过 `data/mysql.json` 连接数据库。

- 主业务库：`zhiyinyunlian`
- 工厂节点库：`zhiyinyunlian_factory_1`、`zhiyinyunlian_factory_2`、`zhiyinyunlian_factory_3`
- 连接配置：`data/mysql.json`，包含限定库权限的应用账号。
- 数据库实际文件：`data/mysql-local/db/`，由MySQL管理，不能直接修改。
- 本机实例管理配置：`data/mysql-local/admin.json`，供初始化、测试和停库使用。

三个节点使用独立数据库和账号，节点账号无法查询其他工厂样本；平台账号不能直接读取节点样本。联合训练通过三个本地进程的HTTP接口交换模型参数。

网页登录和 MySQL 连接分别使用各自的账号。各预置网页演示账号使用相同的初始密码，已有账号沿用现有密码。

| 网页账号 | 权限 |
| --- | --- |
| admin | 平台管理员，可切换三厂 |
| engineer | 星铸工厂质量工程师 |
| operator | 星铸工厂现场人员 |
| manager | 星铸工厂生产负责人 |
| factory_b | 云枢工厂质量工程师 |
| factory_c | 曜光工厂质量工程师 |

## 自定义 MySQL 配置

默认项目实例使用随项目初始化的数据库。若 MySQL 安装在自定义位置，可在运行 `setup.bat` 前设置 `ZY_MYSQLD` 为 `mysqld.exe` 的完整路径。首次配置时若 3307 已被占用，可运行 `.\setup.bat --mysql-port 3308`，网页仍使用默认端口 8765。

若要使用自己管理的MySQL服务，在首次配置前用虚拟环境Python运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B backend/tools/setup_mysql.py
```

按提示输入管理账号。脚本会创建新数据库与专用账号，遇到同名库时会停止。已有业务库连接格式参考 `backend/config.example.json`。常规启动读取 `data/mysql.json`。若仅使用 `ZY_MYSQL_CONFIG` 或数据库环境变量，先准备好 Python 依赖和数据库，再直接运行 `.\.venv\Scripts\python.exe -X utf8 -B run.py --open --workshop`。启动批处理在缺少 `data/mysql.json` 时会尝试初始化项目专用实例。

## Unity 仿真工厂

在 Unity Hub 中添加 `unity/`，使用 **6000.6.7f1** 打开主场景 `Assets/FactoryTwin/Scenes/FactoryCampus.unity`。网页业务只依赖 Python、MySQL 和浏览器，编辑或导出三维工程时使用 Unity。

通过编辑器菜单「质因云联 → 导出 Windows 程序」生成 `unity/Build/Windows/`，然后运行 `unity/启动仿真工厂.bat`。独立程序可用内置数据演示。需要同机读取平台数据时，在 Unity 中连接 `http://127.0.0.1:8765` 并登录网页账号。详见 [Unity 运行说明](unity/运行说明.md)。

### 浏览器内的三维车间

1. 在 Unity 中点「质因云联 → 导出网页三维程序」。需要 WebGL 构建模块。导出的本机文件存放在 `frontend/factory-3d/FactoryCampus/`，从源码克隆后需执行这一步。
2. 双击 `start.bat`。如果是从上一版本更新，先关闭原启动窗口中的服务。用管理员或星铸质量工程师登录，浏览器会自动打开「车间感知」并加载三维车间。构建文件缺失时会打开车间示意图。平时从工作台进入，也可以手动点「车间感知 → 进入三维车间」。
3. 点「准备答辩场景」，核对侧栏的 `EQ-03`、工单和批次。等首条报工后，依次点「注入温控故障」「恢复温控」，待提示「等待复产确认」再点「确认复产」。左键拖动旋转，滚轮缩放。重演时先点「停止演示」。

浏览器版使用当前网页登录会话，并按星铸装配三线 `EQ-03` 对齐演示工单、批次和采集状态。匹配失败或读数过期时，车间暂停设备动画并显示原因。若本轮使用其他设备，可在「生产监控大屏」完成演示。派单、点检和补料也在网页工作台办理。

WebGL 与 Windows 构建产物由 Git 忽略。交付运行包时另行导出完整构建目录。

## 手机浏览器访问

手机浏览器访问同一套网页平台，页面随屏幕尺寸调整布局。手机与电脑连到同一 Wi-Fi 或互通的局域网，先停止占用 8765 端口的原平台服务，再双击 `start-lan.bat`。在手机中打开启动窗口显示的电脑局域网地址。
手机访问平台的8765端口；MySQL的3307端口只监听本机，不需要对手机开放。
遇到防火墙提示，允许Python在自己的可信网络通信。电脑换网后请核对实际联网网卡IPv4地址。

## 演示与停止

### 答辩场景

1. 启动网页，使用管理员或星铸工厂质量工程师登录，进入「生产监控大屏」。如果正在运行普通演示，先停止它，再点「准备答辩场景」。
2. 场景为星铸工厂另建一张模拟工单、一批模拟原料，并准备当前可派单的现场班组长。等首次报工后，点「注入温控故障」，观察温度曲线和停产期间不再增长的报工与耗料。
3. 到「异常与处置」打开温控故障，安排现场检查。现场班组长接单后填写记录并提交。用另一个浏览器配置文件或隐私窗口登录现场账号，可以保留当前管理员会话。
4. 在监控大屏点「恢复温控」。等状态提示「等待复产确认」后点「确认复产」。复产后每累计 3 件汇总一次模拟抽检。质量工程师在现场工单中记录设备点检结论，点检通过后关闭故障。
5. 点「处置记录」查看这次演示的设备、批次、停产和复产时间、报工及耗料。设备点检和复产后的批次抽检分别显示。走下一轮前先停止演示，再点「准备答辩场景」，系统保留上一轮记录。

现有 Unity Windows 发布包读取预置工位的设备 ID。场景用到该工位时，以 Unity 与网页上实际显示的设备、工单、批次和运行状态核对联动。使用其他模拟设备时，Unity 可用于独立展示园区及设备交互。

### 模拟库位补料

1. 在星铸工厂准备答辩场景，等产线开始报工。在「模拟库位补料」点「模拟缺料」。系统会把线边余料退回本批次的模拟库位 A-01，线边库存归零，产线进入缺料停产。
2. 观察当前批次、产量和线边库存。缺料时产量与耗料保持不变。点「从 A-01 补料」，观察库位库存减少、线边库存增加。物料到位后，产线会按原有温控条件恢复报工。
3. 在「处置记录 → 库位补料」核对退料和补料的来源、去向、数量、批次及出入库流水编号，再查看同一批次恢复后的首条报工。也可以用编号到「仓储物料 → 出入库流水」核对原始台账。

这段演示也可以接在温控故障处理完成之后。每个答辩场景可操作一轮补料。重演时，先点「停止演示」，再点「准备答辩场景」。

### 人员与排班

登录后打开左侧 **人员与排班**。管理员可切换三厂；`manager` 负责星铸工厂的员工、班次、排班和请假审批；质量工程师可查看本厂班表及技能信息；`operator` 只看自己的员工档案、班表和请假申请。请假详细原因只对本人和管理人员展示。

推荐体验流程：

1. 用 `admin` 或 `manager` 登录，维护员工的工号、岗位、班组、技能和绑定账号。
2. 在“班次设置”设定开始、结束时间，再“发布排班”，选择日期、产线、所需技能、人数和人员。
3. 提交请假并审批，班表会显示受影响班次的缺员人数。在“调整 / 替班”中取消原人员、选择替班人员并填写说明。
4. 在因果诊断或异常检查中派单，优先显示当班、技能匹配、同产线且待办较少的人员。非当班或技能待核验时需填写调度说明；正在批准请假期间或停用人员不可派单。调度依据保存在工单时间线中。

跨日班次按开始日期归属；排班时间重叠、批准请假冲突、技能不符合会阻止保存。相邻班次休息不足 11 小时会提醒负责人核对，这只是平台提示阈值。人数不足可先发布并显示缺员；请假与班次部分重叠时，保守地按整班不可用提示补员。取消及调整有审计记录，多人同时修改使用版本检查。

“排班当班”根据班表、当前时间与批准请假计算，**不等于考勤或实际到岗**。班次模板修改只影响后续新增排班，已发布班表保留原时间。后台按运行电脑的本地时间处理班次，浏览器按设备日期定位当前班表。界面使用北京时间标注，演示时将电脑和访问设备设为 UTC+8。

首次升级自动新增 5 张 `staff_` 前缀的 MySQL 表，不清空原业务数据。每厂初始化 6 个演示员工、早晚两个班次以及起始 7 天内工作日的模拟班表；工号以 `DEMO-` 开头。初始班表不会随日期自动续排，后续由负责人维护。未绑定登录账号的员工可以参与排班；接收平台工单需要绑定本厂已有登录账号。

建表脚本位于 `backend/sql/workforce.sql`。历史数据可从另行保管的 SQL 备份恢复。常规首次部署使用 `setup.bat` 和 `start.bat` 即可，无需手动导入完整 SQL。

### 生产与算法演示

生产监控页点击“启动演示产线”，预热后观察报工、耗料与检测，可触发短停、换料、温控故障；温控恢复稳定后点击“确认复产”。退出登录不会自动停止后台演示。
因果问答默认使用本地证据助手；也可以配置外部模型。[外部模型配置说明](backend/AI_CONFIG.md)
三路监控视频使用录制素材，动态工况和算法样本来自模拟环境。来源记录和许可见 [素材与数据来源说明](backend/SOURCES.md)。

平台启动窗口按Ctrl+C停止网页服务。MySQL实例保持后台运行。如需停库，先停平台，再在根目录执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m backend.local_mysql --stop
```

下次运行start.bat会自动启动MySQL。不要在MySQL运行时移动项目目录或删除data/mysql-local。

## 验证与数据维护

### 自动化测试

运行 `backend/run-tests.bat` 执行 Python 回归，覆盖启动、登录与权限、库存、工况、处置、排班及联邦训练。测试会创建并清理独立的 `zyyl_test_随机编号` 库。自行管理 MySQL 时，先设置 `ZY_MYSQL_TEST_CONFIG`，指向具有测试库创建权限的管理连接 JSON。

前端测试使用 Node.js，建议使用 Node.js 24。在仓库根目录运行以下命令。

```powershell
node --test backend/tests/frontend-defense.test.mjs backend/tests/frontend-workshop-3d.test.mjs
```

前端用例验证演示记录、补料流水、工单与批次匹配、三维动画条件和操作权限。它们使用模拟输入，可在网页服务关闭时运行。

### 数据迁移与备份

旧SQLite数据的一次性迁移工具是 `backend/tools/migrate_sqlite.py`。目标必须为空库；保留原编号、密码、业务记录和训练模型，并逐行核对。运行期间平台只使用MySQL，SQLite模块仅用于读取旧数据来源。

暂停演示、训练和业务写入后，在根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B backend/tools/backup.py
```

输出为 `data/backups/zyyl-mysql-时间.zip`，含主库与三节点库的标准SQL、上传照片和SHA-256校验文件。恢复时将四份SQL分别导入对应的空MySQL库，将uploads恢复至data/uploads，并配置匹配的账号。不要用直接复制正在运行的MySQL数据目录代替备份。
源码和数据库备份分开保管；不要把含数据库密码的data配置提交到比赛源码中。来源说明见backend/SOURCES.md。
